파서의 매출 레이아웃 인식 조건, 수식 비율에 따른 시트 제외, 블록 분할, 모델 호출·재시도 정책을 이 게시 작업에서 수정하지 않았다. 따라서 알려진 미해석·검증 실패도 그대로 재현된다.

입력 Excel과 manifest, 데이터 생성기, 실제 API 키, 캐시, 실행 결과 파일은 포함하지 않는다. `.env.example`은 빈 API 키를 가진 설정 예시이며 테스트 코드의 가짜 키는 mock 입력이다. 모델 기본 설정의 실제 사용 가능성은 이번에 API로 확인하지 않았다.

## 테스트

저장소 루트에서 다음 명령을 복사본에 실행했다.

```bash
PYTHONPATH=parser/src:parser_ai/src python3 -B -m unittest discover -s parser/tests -q
PYTHONPATH=parser/src:parser_ai/src python3 -B -m unittest discover -s parser_ai/tests -q
```

| 검증 | 결과 |
|---|---|
| 룰베이스·비교 도구 | 85개 중 82개 통과, 외부 데이터 통합 검사 3개 건너뜀 |
| AI mock 테스트 | 87개 모두 통과 |
| 합계 | 169개 통과, 3개 건너뜀, 실패 0개 |
| 비교 CLI 도움말 | 실행 성공 |

AI 테스트에서 HTTPError mock 객체 정리 관련 `ResourceWarning` 4건이 출력됐다. 테스트는 모두 통과했으며 실제 API를 호출하지 않았다. 새로 추가한 재생 실행기는 아래의 실제 기본 더미 재생으로 확인했다.

## 전체 데이터 재생 확인

```bash
python3 -B experiments/replay_session.py /path/to/Data/dummy
```

기본 조직 파일 17개와 마스터 1개를 사용해 재생했다. 입력 데이터는 저장소 밖에서 읽었으며 새 출력 파일은 만들지 않았다.

| 대상 | 룰베이스 금액 집계 일치 | AI 고정 계획 재생 금액 집계 일치 |
|---|---:|---:|
| 조직 파일 17개 | 1,105 / 1,989 (55.6%) | 884 / 1,989 (44.4%) |
| 마스터 1개 | 65 / 117 (55.6%) | 117 / 117 (100%) |

- 앞서 보고한 금액 집계 결과와 일치했다.
- 양쪽 모두 18개 파일 처리를 완료했고, 실행 간 원본 해시가 일치했다.
- 실제 외부 API 요청은 0회다. 재생 응답은 조직 21회·마스터 15회, 총 36회다.
- 재생 보고서의 `summary.logical_calls`는 이 재생 요청 수다. 토큰 관측값 0은 당시 모델 계획 생성에 토큰이나 비용이 들지 않았다는 뜻이 아니며, 그 생성 과정의 사용량과 비용은 미측정이다.
- 추출 검증 전체 통과 파일은 양쪽 모두 0개다. 기존 `예산코드!A178 COMMENT_MISMATCH`가 남아 있다.
- 셀별 정답이 없어 `cell_accuracy`는 `null`이다. 금액 집계 일치와 의미 정확도를 혼동하면 안 된다.
- 시간은 환경과 실행마다 달라지고 모델 계획 작성 시간을 포함하지 않으므로, 이 재생으로 실제 AI 처리속도 우열을 주장하지 않는다.

## 현재 코드의 AI 처리 경로

현재 구조 엔진은 후보 셀 탐색 후 수식 비율 0.3 이상인 시트를 해석 대상에서 제외한다. 후보 행 수가 150개를 넘으면 100행 단위로 먼저 분할하고, 작은 시트의 전체 구조 요청이 타임아웃 나면 블록 요청으로 재시도한다. 따라서 과거 AI README에 기록된 단순한 시트당 1회 가정이나 입력 바이트 수를 현재 호출량으로 그대로 사용할 수 없다.

실제 API 비교는 `parser/compare.py run ... --allow-api`를 사용한다. 이 경로와 고정 계획을 사용하는 `experiments/replay_session.py`는 별개의 실험이다.

재생 계획은 기본 파일명, 행 범위, 코드표 위치를 포함한다. 일부 헤더와 조직코드는 원본을 추가 탐색해 작성했으므로 원래 API 요청보다 넓은 정보를 사용했다. 고정 계획의 재생이 성공해도 새로운 입력에서 모델이 같은 계획을 생성한다는 뜻은 아니다.

## 함수와 호출 관계

기존 파서 함수와 비교 도구는 [함수 명세](../parser/docs/development/function-reference.md)에 정리되어 있다.

추가 재생 실행기는 다음 순서로 동작한다.

`main → load_dataset → ResponsesClient(transport 주입) → run_comparison → 원래 rule/AI adapter → score_manifest → 콘솔 보고서`

| 함수 | 역할 |
|---|---|
| `main()` | 입력 경로 처리, 감사 훅 등록, 두 엔진 실행과 보고서 출력 |
| `deny_writes(event, args)` | 파일 쓰기·네트워크 연결·외부 프로세스 실행 차단 |
| `progress(message)` | 현재 파일을 기억하고 진행 메시지 출력 |
| `transport(body)` | 파일·시트·블록에 맞는 고정 계획을 API 응답 형식으로 반환 |

금액 채점의 정답 출처·완전성 조건·미측정 범위는 [정답셋 문서](parser-comparison-ground-truth.md)를 참고한다.
